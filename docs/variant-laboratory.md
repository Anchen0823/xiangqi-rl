# 四个平级模式与实验规则 lab-v1

界面入口为 **普通象棋 / 变体实验室 / 揭棋 / 翻棋**。变体实验室只负责自定义明棋与子力实验；揭棋、翻棋各有独立入口、棋局和模型。共享实验内核并不表示界面上存在从属关系。

## 启动与操作

本机双击根目录 `变体实验室.cmd`，打开 `http://127.0.0.1:4178/#lab`。页头可以直接切换揭棋 `#jieqi`、翻棋 `#banqi`。重复启动会复用已有的本地服务；关闭服务终端即停止网页服务。网页、Worker、ONNX Runtime WASM 均来自本机，不依赖 CDN，安装并构建后断网可玩。本版不部署公网，也不监听局域网。

双击 `实验室桌面.cmd` 可直接打开 Electron 实验入口，页头仍为四个平级模式。

Electron 的原有启动入口和普通象棋保持不变，页头增加三个平级入口。普通象棋仍由原生 C++、原有 NNUE / 教师后端负责；纯浏览器中的普通象棋入口仍是原项目的界面预览，正式普通象棋对弈请使用桌面入口。三个新增模式在浏览器和桌面都使用真实的 TypeScript 规则与搜索。

首次安装或修改源码后：

```powershell
npm.cmd ci
npm.cmd run lab:build
npm.cmd run lab:serve
```

选择棋子后点击高亮落点；翻棋点击暗子直接翻开。可选本地双人或人机、席位、布局种子和每步预算。翻转只改变显示方向。停止搜索会终止搜索 Worker，停止自动回应并退回基础搜索；再次使用候选需重新载入模型。悔棋、全知研究视角、回放均标记为练习局。

自定义明棋可在“棋子与摆法”编辑组合走法，自由增删棋子、选先行席位，再“检查并应用”。局面 JSON 和 `.xqlab` 均可载入；旧普通象棋 `.xqgame` 由普通象棋入口处理。研究存档含完整暗子身份，请在对局结束后交换存档。揭棋双人暗吃后，吃子者先查看私有回执，按“隐藏并交接”，下一位确认后才能看自己的信息；这是同设备交接保护，不是联网反作弊机制。

## 坐标与初始摆法

9×10 棋盘从红方看，列为 a 至 i、行为 0 至 9，a0 在红方左下。内部格号为 `行 * 宽度 + 列`。席位 0 / 1 与红黑颜色分开表示。标准预设席位 0 执红、红先；翻棋初始席位颜色为空。

标准完整阵容为：

| 颜色 | 将帅 | 士 | 象 | 马 | 车 | 炮 | 兵卒 |
|---|---|---|---|---|---|---|---|
| 红 | e0 | d0、f0 | c0、g0 | b0、h0 | a0、i0 | b2、h2 | a3、c3、e3、g3、i3 |
| 黑 | e9 | d9、f9 | c9、g9 | b9、h9 | a9、i9 | b7、h7 | a6、c6、e6、g6、i6 |

首批预设全部从上表修改，未提及的棋子保留：

| 编号 | 红方修改 | 黑方修改 |
|---|---|---|
| queen-left-3 | 移除 a0、i0 两车，后放 a0 | 增加第三车 e8 |
| queen-right-3 | 移除两车，后放 i0 | 增加第三车 e8 |
| queen-left-2 | 移除两车，后放 a0 | 不变 |
| queen-right-2 | 移除两车，后放 i0 | 不变 |

少子 `ending-2` 仅有红帅 d0、红后 e2，黑将 f9、黑车 a9 / i9；`ending-3` 再加黑车 e7。所有预设提供旋转 180 度并交换棋子颜色的配对局，仍由红方先行。因此后方在一局先行、另一局后行。

**摆法本身可能有强烈战术偏差：ending-2 的红方存在 Qe2–e8 一步将死。** 它是约定的少子对照，不能用来估计一般子力价格。完整阵容、左右后、少子、不同预算都分别报告。

## 自定义明棋

每方恰有一个九宫内的将帅；保留九宫、将帅照面、自陷将军禁止、将死、困毙判负。将帅不允许直接被吃。导入时允许行棋方正在被将军，不允许非行棋方已经被将军。每格最多一子，在棋盘容量内不限制某种棋子的数量。

后沿横、竖、斜线任意距离移动和吃子，不越子，可过河、不受九宫限制。其他组合棋子使用 `PieceDefinition` 的 `moves` / `captures` 分别定义走法，多个组取并集，不能附加脚本、爆炸、召唤或额外回合。

每组包含方向向量、最大重复步数（0 为直到边界）、是否跳跃、相对朝向、蹩腿格、沿路径占位数、目的地活动区域。`relative` 只对黑方反转纵向分量；`blockers` 相对起点，任一格越界或被占则禁止。`screens` 必须恰好满足。非跳跃路径按方向向量的逐次落点计占位；普通滑行使用单位向量，自定义跳跃使用一次向量并明确蹩腿格。区域可为全盘、己方九宫、己方半场或已过河区域。将帅规则不可重定义，新增棋子建议使用新编号，最多 32 种定义。

## 揭棋

9×10 棋盘，将帅明置；每方其余 15 子分别随机扣在本方标准位置，双方都不知道未揭身份。第一步按照原始位置角色行棋，落子后公开真实身份，以后按真身份走。明士可出宫，明象可过河但仍塞象眼；将帅仍受九宫约束，明兵在本方半场只能前进，过河后可横走。被吃暗子的真实身份只向吃子者公开，被吃明子双方可见。这部分采用已确认的 [PyChess 揭棋说明](https://www.pychess.org/variants/jieqi)。

合法着法和将帅安全均使用公开占位角色，不能用未揭真身份判断威胁。随机发牌器只服务裁判，搜索收到的观测不包含发牌种子或完整暗子身份。

## 翻棋

4×8 棋盘（a–d，0–7），32 个标准象棋子整体随机扣放。双方轮流行动，每步选择翻一暗子，或移动本方明子。首翻者取得所翻棋子的颜色，对方取得另一颜色；首翻消耗一个回合。

除炮吃子外，明子上下左右移动一格；普通吃子大小为将、士、象、车、马、炮、兵，同级可吃。兵可吃将，将不能吃兵；不能普通移动吃暗子。炮移动也是一格，只能隔恰好一个占位吃子，不受大小约束，可打明敌子或暗子。若打中的暗子实际为己方，也移除该子，炮落到目标格，目标身份向双方公开；不可主动打已经明置的己方子。

无任何合法动作（包括翻子）或己方棋子全部被吃即负。翻棋没有将军与九宫限制。

## 循环责任与自然限着

以下是完整的 **lab-v1 实验裁决**，不宣称符合正式比赛棋例，不使用子力价格，也不判长杀。

1. 同一棋盘占位、公开身份、暗子占位角色、行棋席位及席位颜色第三次出现，检查最近两个完整循环。稳定棋子 ID 用来追踪追捉目标，不用来区分同种棋子互换后的棋盘。吃子、揭子、翻子会不可逆改变信息状态并重置循环片段；片段内私有吃子信息恒定，因此无需将秘密身份放入公开局面键。
2. 某方在该片段每一步都将军，即长将。否则取其所有非将军着：若每步都新形成对同一稳定目标的合格追捉，判长捉。夹杂将军仍可能长捉；多个攻击者轮流追同一目标也算；轮换不同目标不算。
3. 合格追捉必须是按公开走法、且不自陷将军的吃子威胁。排除目标能立即合法反吃攻击者的互吃兑子；排除假定吃掉目标后，对方任一子能立即合法回吃攻击者的情况；排除该攻击者对该目标在本着之前已经存在、没有重新形成的静态攻击。发现攻击可计入。
4. 明棋和揭棋排除将帅目标、未过河兵目标；排除本次移动的将兵直接追捉。自定义新编号的棋子默认没有豁免。暗子使用公开占位角色；翻棋只认已经翻明的敌子为追捉目标。
5. 双方责任分为无责任、长捉、长将三级。责任较高的一方负，长将优先于长捉；双方同级（包括均无责任）判和。
6. 明棋连续 120 半回合无吃子判和；揭棋连续 120 半回合无吃子或揭子判和；翻棋连续 40 半回合无吃子或翻子判和。将死、困毙或全子被吃优先于同一步触发的和棋计数。

实验运行的 `maxPlies` 是计算截断，不是规则和棋，不进入终局训练标签。

## 内核、搜索与模型

`src/variants/types.ts` 定义版本化 `RuleSet`、`PieceDefinition`、`Scenario`、`Observation`、`Action`、`SearchBudget`；实验记录在 `experiment.ts`。规则 SHA256 由规范 JSON 得出，棋谱、数据、模型均校验规则哈希。规则对象在对弈时视为不可变；编辑需创建新对象。变化后的规则不匹配旧模型时拒载并使用基础搜索。

浏览器裁判 Worker 独自持有真实局面，搜索 Worker 只接收观测。Electron 复用这两个 Worker。Node 批量对局打包同一内核；Python 经常驻 Node JSONL 进程调用裁判，没有第二份 Python 合法着法实现。裁判档案与模型特征分开保存。

明棋为 UCT MCTS，暗棋为多观察者信息集搜索基线：每次模拟从当前玩家知识采样一个可能世界，为各行动者按自身可见信息建立树，并追踪动作可用次数。未知的被吃暗子也参与身份池采样。实现参考 [ISMCTS 原论文](https://eprints.whiterose.ac.uk/id/eprint/75048/)，不声称解决了不完全信息博弈；均匀身份采样没有利用对手行为推断暗子分布。

固定预算计数：初始化根观测记 1 次，每次模拟重新访问采样根记 1 次，每个树内或 rollout 状态转移各记 1 次。单步到达预算即停止，最后一次可以是未完成模拟；结果额外记录模拟数、推理数与耗时。固定种子、预算、模型和参数决定行为；耗时受机器负载影响，不作为节点预算实验的停止条件。交互页面另设 10 秒保护时限，超时不自动落子。

基础搜索仅使用终局胜负，未终局 rollout 返回 0，没有给后定价。网络为 6264 维观测输入、256 / 128 两层 ReLU MLP，8190 个动作 logits 和 tanh 价值。移动索引 `from*90+to`，翻子 `8100+square`。合法掩码在搜索和策略交叉熵中使用；总损失为策略交叉熵加终局价值 MSE。输入含可见棋子、占位角色、颜色/暗子标记、公开库存、本方可知吃子计数及历史摘要，不含暗子真布局。

ONNX Runtime Web 以单线程 WASM 在本地推理，运行库与 WASM 文件随 Vite 构建打包，遵循 [官方 Web 支持说明](https://onnxruntime.ai/docs/tutorials/web/)。候选需同时载入 `.json` 与 `.onnx`，检查规则、特征版本、维度和文件 SHA256。标准 NNUE 和教师引擎不充当变体教师。

训练命令、复现实验及验收证据见 [变体训练与评测](variant-training.md) 和 [本轮验收记录](variant-validation-2026-10-02.md)。
