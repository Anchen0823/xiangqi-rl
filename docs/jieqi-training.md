# 揭棋独立训练

已执行证据：[2026-10-03 试训结果](jieqi-pilot-2026-10-03.md)。
整夜入口：[揭棋 8 小时训练](jieqi-night-8hours.md)，根目录 `训练揭棋8小时.cmd`。

揭棋使用独立策略价值网络与权重，不加载普通象棋 NNUE。
输入来自当前玩家的观测：公开棋盘、暗子占位、可见身份、私有吃子信息和历史摘要。
真实暗子身份仅由 TypeScript 裁判持有。现有不偷看测试验证相同观测和搜索随机源下的决策一致性。

当前网络为 256/128 两层 MLP，合法动作掩码策略头与价值头共享主干。
模型清单绑定规则哈希、特征版本、输入输出维度及 ONNX SHA256。
规则变化后的旧模型必须通过兼容检查。普通 NNUE 不是此模型的初始化来源。

## 启动与恢复

双击根目录 `训练揭棋.cmd`，默认每次建立时间戳目录，预算约 30 分钟。
需要固定目录或恢复时从项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/variants/train-jieqi.ps1 `
  -Minutes 30 -Output runs/jieqi/my-pilot -Nodes 64 -Steps 1000 -Pairs 8 -Device cpu
```

依赖沿用项目 `.venv` 的 PyTorch 和 `trainer/requirements-variants.txt`。
默认 CPU 两线程训练，Node 搜索及 ONNX 单线程；小模型无需占用普通夜训 GPU。

再次执行相同配置、相同输出路径恢复：已完成对局不会换种子重跑；数据冻结后不再增补；
检查点恢复优化器、随机状态和数据游标。恢复调用会获得新的一轮显式时间预算。
不同数据集的继续学习使用同规则旧揭棋权重初始化，并重新建立优化器，不冒充精确恢复。
下一轮从本轮候选继续时，指定 `-Initial runs/jieqi/<本轮目录>/model`，并选择新的 `-Output`。
默认初始权重仍是历史短训候选，便于固定基线复现。

## 本轮协议

约 60% 时间用于上一轮揭棋模型引导的自博弈，最多 512 个训练局，另留 4 个验证局。
每步固定 64 次状态访问，rollout 4；单局上限 1000 半回合。
截断局保存但不进入终局标签；至少 8 个完整训练局与 2 个完整验证局才开始训练。
训练进行 1000 次更新，中点落盘并恢复，然后检查 PyTorch / ONNX 数值一致性，
并计算整个验证集的损失（训练日志中的进度验证仅用前 64 行）。

分别对战基础搜索、上一轮揭棋候选，各预定 8 对换色局；两种对手交替执行。
自博弈、验证、两组评测的种子域互不重叠；揭棋换色使用镜像同一布局。
模型和搜索预算固定，不使用评测结果挑选本轮检查点，也不自动替换冠军。

30 分钟为整局边界上的软时间上限，训练和导出仍须完成；单局可能使实际耗时略超预算。
如果先达到数据上限且评测全部完成，可提前结束。预算耗尽时剩余评测保持缺失，
报告给出完成率、缺失结果上下界，未完成组不伪造整体置信区间。
若不足最低训练样本，运行停止并保留证据；再次用相同配置执行，可继续积累样本。

## 查看与试玩

`status.json` 查看当前阶段，`summary.json` 查看最终计数。
`report.html` 是试训总览，两种对手可直接比较。
两组 `evaluation/*/report.html` 是中文报告；每组用整对得分的 Hoeffding 95% 区间。
在揭棋网页中加载同一 `model/` 下的 `candidate.json` 与 `candidate.onnx` 即可试玩。
低训练损失或少量胜局均不能证明棋力提升，短训结果只作为实验线索。

目录总览见 [项目结构](project-structure.md)，共享规则见 [玩法说明](variant-laboratory.md)。

运行后审计全部数据、逐局终局、固定预算与模型实际决策复现：

```powershell
$env:PYTHONPATH='trainer/src'
.venv/Scripts/python.exe scripts/variants/verify-jieqi-run.py runs/jieqi/my-pilot
```

输出 `audit.json`，包含逐局回放数量、样本数、终局原因、ONNX 一致性以及
新旧模型在同一完整验证集上的指标。审计不把低损失视为棋力证据。
